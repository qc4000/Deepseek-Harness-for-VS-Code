# 任务清单 NNN：<能力名称>

> 用法：任务按「先红后绿」排序；每完成一项把 `[ ]` 改成 `[x]` 并在 PR 里贴 `npm test` 结果。
> 粒度：单项 ≤ 半个工作日。`[P]` 表示与相邻任务无依赖、可并行。`[test]` 必须先于对应 `[impl]` 合入。

## 阶段 0 · 准备（基础设施）

- [ ] `[impl]` <常量/配置项键名/消息类型> 落位 —— 判据：<…>
- [ ] `[impl]` 新纯函数挂到 `module.exports.__internals` —— 判据：测试可直接取到
- [ ] `[test]` 创建 `test/<主题>.test.js` 骨架（vscode 桩 + `ok()`） —— 判据：`node test/<主题>.test.js` 能跑到第一断言

## 阶段 1 · 纯逻辑（L1）

- [ ] `[test]` AC-1 正面用例 —— 判据：当前失败（红），原因与预期一致
- [ ] `[impl]` 实现最小逻辑 —— 判据：上一条变绿
- [ ] `[test]` AC-3 非法输入/边界（空、超长、越界、控制字符） —— 判据：红
- [ ] `[impl]` 收敛与拒绝逻辑 —— 判据：绿，且提示文案包含下一步动作
- [ ] `[test]` AC-2 关闭开关后不生效 —— 判据：红→绿

## 阶段 2 · 宿主接入（L2）

- [ ] `[test]` webview/宿主消息协议（`origin`/`source`/字段校验/长度截断） —— 判据：红
- [ ] `[impl]` `handleWebviewMessage` / 中继脚本接入 —— 判据：绿
- [ ] `[test]` 失败路径：超时、回执失败、面板未加载 —— 判据：有明确提示且可回退
- [ ] `[impl]` 提示与回退实现 —— 判据：绿

## 阶段 3 · 页面侧 / 平台（L3）

- [ ] `[test]` 插件客户端仿真（未握手不介入 / 回执语义 / 修饰键 / 独立浏览器） —— 判据：红
- [ ] `[impl]` `dsh-plugins/<plugin>/lib/client.js` 实现（ES5 风格） —— 判据：绿
- [ ] `[test]` `[P]` 平台分支（win32 / posix / macOS 门控） —— 判据：绿
- [ ] `[impl]` 插件版本号提升（`package.json`，单一源头） —— 判据：扩展能识别并覆盖安装

## 阶段 4 · 文档与发布

- [ ] `[docs]` `docs/TESTING.md` 测试地图补行（套件 / 断言数 / 覆盖）
- [ ] `[docs]` `README.md` 配置表与行为说明（若用户可见）
- [ ] `[docs]` `CHANGELOG.md` 顶部新版本小节
- [ ] `[impl]` `package.json` 版本号提升（与 CHANGELOG 一致）
- [ ] `[docs]` `spec.md` 状态改 `implemented`，补「验证记录」（套件 + 断言数 + 实机结论）
- [ ] `[impl]` 打 tag `v<版本>` 并确认 Release 工作流绿
