## 1. 背景与问题

016 的缩放校准按 `ratio = iframe 实宽 ÷ 插件上报的 innerWidth` 换算裁剪，假设两者「同拍」。
019 的事件流日志第一次把这个假设放到实机上检验（2026-11-12 用户日志）：

- `[env] window.zoomLevel=0 editor.fontSize=16 fontScale=1` —— 正确比例**应当恒为 1**；
- 但 `[sidebar-trace]` 里出现 `ratio=1.3455 / 1.1484 / 1.0471 / 0.8777`，且都紧邻 `resize`；
- 同一批日志里 `rect == clip`（盒因子 1），说明不是 CSS zoom 盒子问题。

结论：**拖动瞬间 `innerWidth` 是页面按旧宽度测的、`rect` 是宿主按新宽度量的，两者不同拍**，
相除得到的就是「拖动幅度 / 面板宽」这类假比例。后果：拖动时裁剪被乘错——
`1.3455` 让导轨多裁 19px，`0.8777` 让展开态 284→246，**少裁 34px 露出侧栏**。

## 2. 目标

- 只有**同一拍**的两个量才参与换算：宿主主动发 `request-layout` 要一次样本（页面收到后按
  当前裁剪重排再报），并在应答到达时校验「面板宽与请求时一致」，才把 `ratio` 记为可信。
- 其它来源（自发上报、拖动中的应答、越界值）一律不采信，沿用上次可信比例（初始为 1 = 015 行为）。
- 一旦可信比例存在，后续裁剪直接使用，不再反复请求（零额外消息）。
- 字号缩放变化（`dsh-font-scale`）时作废旧比例并重新要一次配对样本。
- 在日志里留痕：`ratio-request` / `ratio-set` / `ratio-fallback`，便于事后核对。

## 3. 非目标

- 不改变 016 的「不做预测、不做回写」原则（本规格只改**采信条件**）。
- 不改抽屉态 `crop=0`、不改 auto 去抖、不改手动覆盖语义。
- 不做「每次拖动都校准」——那正是假比例的来源。

## 4. 用户故事

- 作为 **VS Code 用户**，我拖动面板时裁剪不应忽多忽少（既不该多切内容，也不该露出侧栏条）。
- 作为 **维护者**，我希望缩放校准只在证据成立时生效，日志能显示「这次比例是怎么来的」。

## 5. 验收标准（必须可执行）

- **AC-1（首次未配对不采信）**：Given 未校准、收到一条自发 `layout`（`innerWidth` 来自旧布局），
  Then 裁剪按 `ratio=1`，并发出**一次** `request-layout`（`ratio-request` 留痕）。
- **AC-2（配对样本采信）**：Given 面板宽未变、应答携带当前裁剪对应的 `innerWidth`（如 `s=0.875`），
  Then `ratio` 记为 0.875，导轨裁剪 `56×0.875=49`、展开 `(280+4)×0.875=249`。
- **AC-3（拖动中样本作废）**：Given 请求发出后 `stage` 变了（用户继续拖动），When 应答到达，
  Then 该样本作废、比例不更新、裁剪仍按上次可信值（1）——不得出现 1.05~1.35 这类假比例。
- **AC-4（幂等与限流）**：Given 已有可信比例，Then 后续裁剪不再发校准请求；
  Given 未校准，Then 请求限流 500ms，避免拖动中刷屏。
- **AC-5（字号变化重校）**：Given 运行时改 `editor.fontSize`（`dsh-font-scale`），Then 旧比例作废并
  重新要一次配对样本。
- **AC-6（越界与缺失）**：`innerWidth` 缺失/≤0/非数、`ratio` 越界（<0.5 或 >2）→ 回退到上次可信值
  （初始 1），记 `ratio-fallback`。
- **AC-7（收敛不回退）**：四档缩放 × 240–1400 固定点扫描仍收敛、无 2-周期、分段期望
  `round(轨道×s)`（扫描需模拟「页面收到请求后按当前裁剪重排」）。

## 6. 兼容矩阵

| 场景 | 行为 | 说明 |
| --- | --- | --- |
| 缩放 = 1（用户当前环境） | 配对样本 ratio=1，行为与 015 完全一致 | 日志不再出现假比例 |
| 缩放 ≠ 1 | 配对后按实测比例裁 | 未配对前按 1（安全回退） |
| 旧插件（无 `innerWidth`） | 恒按 1 | 015 行为 |
| 拖动中 | 一律不更新比例 | 这次日志暴露的问题 |
| 抽屉态 | 恒 0，且不发校准请求 | 轨道 0 无需换算 |

## 7. 约束（引用宪法）

- 第三条：越界/回退有日志留痕（`ratio-fallback`），不静默。
- 第五条：`request-layout` 不携带任何用户输入；`innerWidth` 校验为正有限数。
- 第六条：AC-1..AC-7 全部离线可测（vm 中继 + 插件仿真 + 扫描派发请求）。

## 8. 失败与提示

| 失败场景 | 行为 | 出口 |
| --- | --- | --- |
| 请求发出后一直没应答 | 比例保持上次可信值（初始 1），500ms 后重试 | 无需用户操作 |
| 应答时面板已变 | 作废该样本（不提示，属预期） | 下一次静置再校准 |
| 比例越界 | 回退 + `ratio-fallback` 留痕 | 查看日志/导入诊断 |

## 9. 风险与开放问题

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 每次进入「需要裁剪」都请求一次 | 多一条消息（已校准则不请求） | 仅在未校准时请求 + 500ms 限流 |
| 无应答的 dsh 版本 | 比例恒 1（= 015 行为） | 安全回退，不影响裁剪正确性 |
| 盒模型仍未验证（`rect/(stage+crop)`） | 若盒子被缩放，比例会偏 | 日志已含 `rect/clip`，实机可判定（019） |
