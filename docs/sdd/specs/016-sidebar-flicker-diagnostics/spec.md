## 1. 背景与问题

spec 015 修掉了抽屉态（<768px）的「裁 280 切对话区」与 488–711px 的静态 2-周期振荡，但用户实测仍有残留：

1. **拖动 VS Code 侧边栏宽度时，DSH 侧栏会不停闪烁**，且「只能再拉一下才停止」；
2. **调整 VS Code 界面缩放（`window.zoomLevel`）后更容易出现**。

离线固定点扫描证明：把裁剪口径改成「grid 首轨道」后，**静态**回路在任何宽度都单调收敛（无 2-周期）。
因此残留现象必然来自静态模型没有覆盖的因素，已定位到两个：

- **缩放单位错位（004 §10 一直悬着的「先验证 zoom 语义」）**：插件上报的是 DSH 内部 CSS px，
  宿主裁剪的是 webview CSS px；`#dsh-frame` 带 `zoom: s`（`editor.fontSize/16`，默认 14 → 0.875）。
  证据：004 §12 记录「非 1 倍字号残留约 66px 侧栏条」，`264 × (1.25 − 1) = 66` 精确命中 →
  **侧栏视觉宽 = 轨道 × s**，而裁剪用的是未缩放的轨道值：`s>1` 残留一条 DSH 侧栏条
  （拖动时该条内容在导轨/展开/抽屉之间来回换 → 用户看到「侧栏不停闪」）；`s<1`（默认）多切
  `轨道×(1−s)` 的对话区（展开态 ≈35px）。1.0.2 的失败是「zoom 乘算 + 断点预测 + 立即回写」捆绑所致，
  本规格**只做实测校准、不做任何预测/回写**（004 §10 的原计划）。
- **auto 策略在 1024 断点逐帧重算**：拖动时 `window.resize` 每帧触发 `computeHidden()`，
  在断点附近来回翻转 `hidden` → 裁剪反复开关 → 侧栏反复显隐。

另外，这两类现场**目前无法取证**（页面跨源、宿主看不到插件内部）：015 的离线模型只能证明
「模型内不振荡」，不能证明「实机不振荡」。因此本规格按用户要求先补**诊断日志**：
插件侧环形日志 + 异常自动上报 + 宿主合并上报 + 输出面板 + 手动导出命令，做到
「下次再闪，一条命令就能拿到两侧现场」。

## 2. 目标

- 裁剪量按**实测比例**换算：`crop = round((轨道 + 手柄余量) × ratio)`，
  `ratio = iframe 实宽 / 插件上报的 innerWidth`（同一份上报里配对，天然同拍）；
  非 1 倍字号下不再残留侧栏条、不再多切对话区。
- 拖动时 auto 策略不逐帧翻转：`hidden` 重算去抖（松手后 150ms 生效一次），静态规则与 004 完全一致。
- 插件有环形日志：测量、上报、收到的宿主消息、转调结果、band 翻转都留痕（有上限、不落盘、无敏感数据）。
- **band 翻转风暴自动取证**：1s 内折叠/抽屉态翻转超过阈值 → 插件自动把日志连同宿主日志一并交给扩展，
  写入输出面板并给一次可见提示；用户也可用命令随时手动导出。
- 下一次复现时，日志必须能回答：当时的 stage/crop/ratio/innerWidth/轨道/折叠/抽屉态/缩放配置是什么、
  翻转以什么序列发生（004 §10 要求的「实测量自校准」证据链）。

## 3. 非目标

- 不做任何「预测/预写裁剪值」（004 §10/§12 明确否决的 1.0.2 路径）。
- 不改 004 的静态规则：`auto` 仍是 `<1024` 隐藏、`show/hide/手动覆盖` 优先级不变（只加去抖时序）。
- 不把日志落盘、不上报任何 token/路径/对话内容（只有布局数值与短枚举）。
- 不改 DSH 页面 DOM/事件（插件仍只 postMessage + 公开服务，015 的转调路径不变）。
- 不处理 spec 004 §12 的「折叠动画 300ms 与裁剪不同步」瞬态露出（记录在案，另议）。

## 4. 用户故事

- 作为 **VS Code 用户**，我希望拖动侧栏宽度、调整界面缩放时 DSH 侧栏不再闪，或至少一条命令就能把
  现场日志交出来，而不是只能凭感觉描述。
- 作为 **DSH 二次开发者**，我希望本扩展按 DSH 页面的**真实像素**换算裁剪量，别再因为字号缩放把我的
  导轨/侧栏裁成半截或露出一条。
- 作为 **维护者**，我希望下次有人报「又闪了」时，输出面板里就有两侧时间线，不用再靠推理解题。

## 5. 验收标准（必须可执行）

- **AC-1（插件环形日志）**：Given 插件已握手并上报过、宿主发过 `layout-toggle`/`request-layout`，
  When 调 `window.__dshVscodeLayout.logs()`，Then 返回带时间戳的条目（`ev` 形如 `ack|recv|report|flip|
  toggle|diag`，`v` 为 `k=v` 紧凑串，含 `w/collapsed/drawer/innerWidth/dpr` 关键字段），条数 ≤ 120 且
  超限丢最旧；`clear()` 后为空；上报字段变化与 band 翻转各留一条。
- **AC-2（翻转风暴自动取证）**： Given 1000ms 内 band 翻转（`collapsed`/`drawer` 变化）≥7 次，
  Then 插件向宿主发 `layout-diag{reason:'flip-storm', entries(≤200)}`，10s 内不重复触发；
  宿主合并自身日志回 `dsh-sidebar-diag` → 扩展写入输出面板「DeepSeek Harness」并给一次状态栏提示
  （含「导出侧栏诊断」出口），重复风暴不刷屏。
- **AC-3（手动导出）**： When 执行命令 `dshPanel.diagnoseSidebar`，Then 扩展发 `dsh-sidebar-diag-request`
  → webview 向页面发 `layout-diag-request` 并在 600ms 内合并回包（插件日志 + 宿主日志 + 扩展侧环境
  `window.zoomLevel/editor.fontSize/fontScale`），输出面板显示该块；**老插件不回包**时超时兜底：
  仍输出宿主日志并标注 `plugin=unavailable`（不静默）；面板未打开时给中文信息提示。
- **AC-4（比例校准）**： Given 插件上报**配对样本**（宿主 `request-layout` 应答、且面板宽未变）
  `{sidebarWidth:56, collapsed:true, drawer:false, innerWidth:1056/0.875}`，Then 裁剪 `round(56×0.875)=49`；
  展开态 `{280,false}` → `249`；ratio=1.25 → 导轨 `70`、展开 `355`；
  `innerWidth` 缺失/≤0/非数、iframe 实宽 ≤0、或 ratio 越界（<0.5 或 >2）→ 回退上次可信值（初始 1）
  并记 `ratio-fallback`；抽屉态仍恒 0。
  **采信条件修订（020，2026-11-12）**：只有「请求-应答配对」的样本才算数——自发上报（尤其拖动中）
  一律不采信，详见 [spec 020](../020-ratio-pairing/spec.md)。
- **AC-5（不振荡回归，含缩放）**： Given `policy=auto`、比例 `s ∈ {0.75, 0.875, 1, 1.25}`、
  面板宽 240–1400 逐档，When 跑 015 的固定点扫描（`innerWidth = (面板宽 + crop)/s` 回喂），
  Then 每档 ≤40 次收敛、无重复值，收敛值分段为 `stage ≥ 1024 → 0`、`stage < 768s → 0`、
  `[768s, 968s) → round(56s)`、`≥ 968s → round(284s)`，且 `crop ≤ round((轨道 + 4) × s)`。
- **AC-6（auto 去抖）**： Given `policy=auto` 且面板在 1024 附近连续 resize（模拟拖动），
  Then 150ms 静默期内不重算 `hidden`、不改裁剪；静默后按**最终**宽度只翻一次；
  初始加载立即按宽度计算；`show/hide/手动覆盖` 分支不参与去抖（立即生效）。
- **AC-7（既有不回退）**： When 跑 `npm run test:one -- dsh-sidebar`，Then 004/015 的既有断言
  （按钮分流、抽屉态恒 0、老插件缺字段走老语义、`show` 零介入、unavailable 提示、安装幂等）全绿。

## 6. 兼容矩阵

| 场景 | 新插件（0.3.0） | 旧插件（≤0.2.0，未重启 dsh web） | 说明 |
| --- | --- | --- | --- |
| 字号缩放 = 1 | `ratio≈1` → 与 015 数值一致 | 无 `innerWidth` → `ratio=1` → 同左 | 校准只在可测时生效 |
| 字号缩放 ≠ 1 | 按实测 ratio 换算，无残留条/无多切 | 维持 015（有残留/多切），靠安装提示「重启 dsh web」 | 回退路径 |
| 抽屉态 <768 | 仍恒 0，不受 ratio 影响 | 同左（015 行为） | — |
| 拖动跨 1024 | 去抖 150ms 后只翻一次 | 同左（去抖在宿主侧） | 宿主逻辑与插件版本无关 |
| 抖动取证 | 自动上报 + 命令导出 | 无插件日志 → 超时兜底只出宿主日志并标注 | 不静默 |
| `dshPanel.dshSidebar=show` | 不安装插件、不裁剪、命令导出仅宿主日志 | 同左 | 能力总关 |
| 系统浏览器打开 DSH | 不适用（插件未握手不介入） | 同左 | — |

## 7. 约束（引用宪法）

- **第一条**：日志只在宿主握手后采集与上报；插件仍不改 DOM、不拦交互；`show` 策略不装插件。
- **第三条**：ratio 回退、老插件不回包、面板未打开都必须有可见提示；禁止「点了没反应」。
- **第四条**：004/015 既有行为全部保留（AC-7）；旧插件缺字段走 015 语义。
- **第五条**：诊断消息字段白名单 + 长度/条数上限（`ev` 形状、`v` 可打印 ASCII、条目 ≤200），
  扩展侧净化后再落输出面板；不新增权限、不落盘、不含 token/路径/对话内容。
- **第六条**：比例换算与去抖判定必须离线可测（AC-4/5/6）。
- **第七条**：新增命令同步 `package.json` 贡献点与 README；行为变更写 CHANGELOG（发版时）。

## 8. 失败与提示

| 失败场景 | 用户可见提示 | 出口动作 |
| --- | --- | --- |
| `innerWidth`/实宽缺失或 ratio 越界 | 不提示（正常回退 `ratio=1`，行为=015），日志记 `ratio-fallback` | 复现后用命令导出日志查原因 |
| 翻转风暴 | 状态栏一次「检测到 DSH 侧栏抖动，诊断已写入输出面板（命令：DeepSeek Harness: 导出 DSH 侧栏诊断）」 | 打开输出面板复制日志 |
| 手动导出但面板未打开 | 信息提示「DeepSeek Harness 面板尚未打开，请先点击侧边栏图标。」 | 先打开面板 |
| 手动导出但页面无回包（老插件/加载中） | 1.5s 后输出面板写明「未收到页面回包（插件未生效？可点「重启 dsh web」）」，仍附宿主日志 | 重启 dsh web |
| 输出通道写入失败 | `console.warn` + 状态栏提示一次 | 反馈维护者 |

## 9. 风险与开放问题

| 风险 / 未知 | 影响 | 应对 / 待验证 |
| --- | --- | --- |
| ratio 模型仍与真实渲染有出入（CSS zoom 语义未定论） | 校准方向对但数值可能仍偏 | 日志同时记录 `rect / (stage+crop)`（盒因子）与 `ratio`，实机一次即可判定 004 §10 悬案；AC-4 只约束公式本身 |
| 去抖让断点附近晚 150ms 才隐/显 | 拖动结束瞬间的一次性跳变 | 只影响 `auto`；静态规则不变（AC-6），可被手动覆盖即时覆盖 |
| 自动取证被误触发（DSH 正常动画期间高频翻转） | 输出面板出现噪声块 | 10s 限流 + 状态栏每窗口一次；阈值 7 次/1s 写成常量便于调整 |
| 用户复现时日志已被环形缓冲挤掉关键段 | 取证不全 | 环形 120 条 + 风暴触发即整体上报（含触发前现场） |
