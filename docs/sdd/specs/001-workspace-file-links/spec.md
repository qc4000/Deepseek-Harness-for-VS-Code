> 后续修改该能力时，先改本文件的 AC 与兼容矩阵，再改代码与测试。

## 1. 背景与问题

DSH 把模型回答里的工作区路径（`src/a.ts`、`docs/`）渲染为可点击按钮，点击后在 **DSH 右侧边栏**
打开。但用户此时在 VS Code 里工作：希望点击后直接在 **VS Code 资源管理器**定位/打开，
而不是切到 DSH 内置查看器。扩展不能为此改写 DSH 页面（宪法第一条），只能在
「握手后的只读监听」范围内接管这一次点击。

## 2. 目标

- 面板内点击工作区文件链接：资源管理器选中 + 编辑器打开（非预览标签页）。
- 面板内点击工作区文件夹链接：资源管理器选中，不额外打开编辑器。
- 任何无法处理的点击都**回放原始点击**，保持 DSH 原行为（绝不「点了没反应」）。
- 行为可配置关闭（三种模式），关闭时插件不安装、不握手、不介入。

## 3. 非目标

- 不接管 DSH 侧边栏内部的链接、不接管 DSH 自己的文件预览器。
- 不修改 DSH 页面 DOM、不注入样式。
- 不在系统浏览器打开的 DSH 中生效（那里没有外层宿主）。
- 不解析链接行号并定位（`:12` / `#L12` 只用于提高路径命中率，编辑器停在第 1 行；见 `003` 候选）。

## 4. 用户故事

- 作为 **VS Code 用户**，我希望点击回答里的文件路径就在资源管理器定位并打开，
  以便不离开编辑器就能核对模型改了什么。
- 作为 **DSH 二次开发者**，我希望这套接管在我不需要时能完全关闭、且不影响我自己改的页面，
  以便我的定制不被干扰。

## 5. 验收标准

- **AC-1**：Given 目标文件位于当前工作区且存在、`workspaceFileLinkAction=revealAndOpen`，
  When 在面板内点击 `src/a.ts`，Then 资源管理器定位并选中该文件，且用非预览标签页打开编辑器。
- **AC-2**：Given 目标为文件夹（`docs/`）且存在，When 点击，Then 仅在资源管理器定位，不打开编辑器。
- **AC-3**：Given 目标为绝对路径、`../` 越出工作区、或 `stat` 失败，When 点击，
  Then 不发成功回执、状态栏提示「DSH 链接不在当前 VS Code 工作区内：<path>」（超长截断），
  插件回放原始点击，DSH 侧边栏照旧打开。
- **AC-4**：Given 点击时按住 `Ctrl`/`Cmd`/`Shift`/`Alt`，When 点击文件链接，
  Then 扩展完全不介入，直接走 DSH 自身行为。
- **AC-5**：Given 插件尚未收到宿主 `ack`（独立浏览器 / 其它宿主 / 面板未就绪），
  When 点击文件链接，Then 插件不阻断、不发消息，DSH 原行为不受影响。
- **AC-6**：Given 已发 `reveal` 但 2500ms 内无回执（面板关闭、扩展未升级），
  When 超时，Then 自动回放原始点击。
- **AC-7**：Given `workspaceFileLinkAction=off`，Then 不安装/不更新插件、webview 不发 `ack`、
  点击完全走 DSH 行为；Given `revealOnly`，Then 只定位不打开编辑器。
- **AC-8**：Given 插件文件已随扩展分发且版本一致，When 再次打开面板，Then 安装幂等
  （不重写文件、不提示重启、不写 `dependencies`）。

## 6. 兼容矩阵

| 场景 | 新版 dsh | 旧版 dsh | 说明 |
| --- | --- | --- | --- |
| Windows 本地 | 接管 | 接管 | 路径分隔符归一化为 `/` 后再比较 |
| macOS 本地 | 接管 | 接管 | 大小写不敏感比较 |
| Linux 本地 | 接管 | 接管 | 大小写敏感比较 |
| WSL Remote | 接管（面板内） | 接管 | 扩展宿主与工作区在远端，路径为远端路径 |
| Remote-SSH / Dev Containers | 接管（面板内） | 接管 | 同上；不依赖认证代理 |
| 系统浏览器打开 DSH | 不介入 | 不介入 | 无外层宿主，插件保持惰性 |
| 多工作区（Multi-root） | 接管 | 接管 | 相对路径对每个工作区文件夹依次尝试 |
| `workspaceFileLinkAction=off` | 不介入 | 不介入 | 不安装插件、不发 ack |

## 7. 约束

- 宪法第一条：插件只在 `ack` 后接管，只监听文件链接按钮的点击，失败回放；
  用户可用配置完全关闭。
- 宪法第五条：路径必须 `normalizeLinkPath` → 去行号 → 候选 Uri → `isInsideFolder` 且 `stat` 成功；
  绝对路径与 `../` 越界拒绝；消息字段截断（`token` 64、`path` 4096）。
- 配置项 `dshPanel.workspaceFileLinkAction`：`revealAndOpen`（默认）/ `revealOnly` / `off`。
- 插件版本以 `dsh-plugins/dsh-vscode-file-links/package.json` 为单一源头。

## 8. 失败与提示

| 失败场景 | 用户可见提示 | 出口动作 |
| --- | --- | --- |
| 目标不在工作区 / 不存在 | 状态栏「DSH 链接不在当前 VS Code 工作区内：…」（4s） | 插件回放 → DSH 侧边栏打开 |
| 宿主无回执（超时） | 无额外提示（保持原行为） | 插件回放原始点击 |
| 插件安装/写入失败 | 警告「安装 DSH 工作区文件链接插件 … 失败：<原因>」 | 面板照常可用，链接保持 DSH 行为 |
| 插件刚安装/升级 | 信息「已自动安装/更新 DSH 插件（…），请点击面板顶部的「重启 dsh web」使其生效」 | 用户重启 dsh web |

## 9. 风险与已知限制

| 风险 / 未知 | 影响 | 应对 |
| --- | --- | --- |
| DSH 前端把类名从 `fileLink` 改名 | 插件认不出按钮 | 按 token 局部名匹配（不绑完整哈希类名）；失效时行为回落到 DSH（不阻断） |
| 链接带行号 | 编辑器停在第 1 行 | 已知限制，候选规格 `003` |
| 面板未安装插件即点击 | 无接管 | 回落到 DSH 行为（不报错） |
