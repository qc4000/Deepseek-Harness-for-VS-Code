## 1. 背景与问题

spec 015 规定：抽屉态（dsh 0.2.2+ 的 `<768px`）下顶部按钮**只**转调 DSH 原生收放，**不写**手动覆盖
（`dsh.ui.dshSidebarHidden`）。这在「一直待在抽屉态」时是对的，但**跨断点就丢了用户意图**：

1. 面板较窄（<768，抽屉态），用户点按钮选了「显示」（DSH 抽屉打开）；
2. 把面板拉宽到 768–1024（回到 grid 导轨）或 ≥1024；
3. 宿主仍按 `auto`（`<1024` 隐藏）重新裁剪 → 侧栏**又变回隐藏**。

用户实测（2026-11-12）：确实如此。诊断日志里可复现的特征是——抽屉态点击只留一条
`toggle from=user drawer=1`，**没有任何 `hidden` 条目**；拉宽后出现 `layout w=56 c=1 d=0 … crop>0`。

**更深一层（本次定位）**：页面内的覆盖态 `sidebarOverride` **只在构建 HTML 时注入一次**，手动切换时
从未同步它。因此即便覆盖已写进 `globalState`，当前页面里 `sidebarOverride` 仍是 `null`，下一次
`resize` 的 auto 重算（016 去抖）会重新执行 `computeHidden()` → `<1024` 隐藏 → 把用户刚选的选择冲掉。
这条在 **grid 态同样存在**（手动显示/隐藏后只要拖动面板就会被重置），抽屉态只是拉宽时必现。

## 2. 目标

- 抽屉态按钮/命令同时表达并**持久化**用户意图：点「显示」→ 覆盖 `hidden=false`；点「隐藏」→ `hidden=true`；
  与 DSH 原生抽屉动作一并下发给页面（转调照旧）。
- 拉宽离开抽屉态后，宿主按该覆盖继续执行（显示则 `crop=0`，隐藏则按轨道裁剪），不再被 `auto` 覆盖。
- 不改变 grid 态既有语义、不改变抽屉态 `crop` 恒 0、不改变转调失败提示与回执链路。

## 3. 非目标

- 不改 `auto` 的 1024 断点规则与 150ms 去抖（spec 016）。
- 不让宿主主动改 DSH 抽屉状态以外的东西（仍只调 `ctx.layout.toggleSidebar()` 一次）。
- 不新增配置项、不新增用户可见提示（沿用 015 的转调失败提示）。

## 4. 用户故事

- 作为 **VS Code 用户**，我在窄面板里手动显示了 DSH 侧栏，之后的拉宽/拉窄都应保持我的选择，而不是把侧栏藏回去。
- 作为 **DSH 二次开发者**，我希望「显示/隐藏」是一份明确、可持久的用户偏好，而不是随窗口宽度漂移的临时状态。

## 5. 验收标准（必须可执行）

- **AC-1**：Given 抽屉态（上报 `drawer=true`、`collapsed=true`）且策略 `auto`，When 点工具条按钮（或宿主命令
  `dsh-sidebar-toggle`），Then 向扩展发 `dsh-sidebar-state{hidden:false, reason:'user'}` **且**向页面发
  `layout-toggle`；随后拉宽到 900（grid 导轨，`auto` 本会隐藏）与 1200，Then `--dsh-crop` 恒为 `0px`、
  按钮 `aria-label` 保持「隐藏 DSH 侧栏」。
- **AC-2**：Given 抽屉态且抽屉已展开（`collapsed=false`），When 点按钮（意图=隐藏），Then 覆盖 `hidden=true`；
  拉宽到 900 后 Then `--dsh-crop = round(56 × ratio)`（按用户意图隐藏）。
- **AC-3**：既有不回退——抽屉态 `crop` 恒 `0`；每次点击仍只发**一条** `layout-toggle`；grid 态点按钮仍走
  「切裁剪 + 写覆盖」；转调失败（`unsupported`/`failed`）仍上报 `dsh-sidebar-toggle-failed` 并提示一次。
- **AC-4**：Given 覆盖已写入，When 拖动过程中 `resize` 去抖回调触发，Then 覆盖分支不重算 `hidden`
  （覆盖优先，不被 `auto` 覆盖）。
- **AC-5**：Given 覆盖 `hidden=false`，When 用户随后把面板拉回抽屉态，Then 抽屉态展示态仍由 `collapsed`
  驱动（按钮标签语义不变），`crop` 仍为 `0`。
- **AC-6**：Given grid 态（`auto`，900px 已隐藏），When 手动点「显示」后再拖动面板到 1000px
  （触发 150ms 去抖重算），Then `crop` 仍为 `0`——页面内覆盖态必须与手动切换同步，auto 重算不得冲掉用户选择。

## 6. 兼容矩阵

| 场景 | 行为 | 说明 |
| --- | --- | --- |
| 新插件 + 抽屉态点击 | 写覆盖 + 转调 | 本规格 |
| 新插件 + grid 态点击 | 切裁剪 + 写覆盖 | 004/015 既有 |
| 旧插件（无 `drawer` 字段） | 走 grid 语义（不可达抽屉分支） | 015 回退 |
| 转调失败（`unsupported`/`failed`） | 覆盖仍按用户意图写入；状态栏提示一次 | 意图优先 |
| `dshPanel.dshSidebar=show` | 不装插件、不写覆盖 | 能力总关 |

## 7. 约束（引用宪法）

- 第一条：抽屉态分支仍只发 `postMessage` + 调一次公开服务；不写 DOM、不拦交互。
- 第三条：失败提示沿用 015（不新增静默分支）。
- 第四条：旧插件/旧 dsh 走既有回退；grid 语义零变化。
- 第五条：`dsh-sidebar-state` 仍只带 `{hidden:boolean, reason:'user'}`，由既有扩展分支持久化。
- 第六条：AC-1..AC-5 全部可在 `test/dsh-sidebar.test.js` 离线断言。

## 8. 失败与提示

| 失败场景 | 用户可见提示 | 出口动作 |
| --- | --- | --- |
| 转调失败（服务缺失/抛错） | 015 既有状态栏提示（每类一次） | 重启 dsh web / 升级 dsh |
| 面板未测量（`inDrawer()` 不可达） | 走 grid 语义，无新增提示 | 等测量到位后按钮自动切换语义 |

## 9. 风险与开放问题

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 抽屉态点开又点关会连续改覆盖 | 覆盖随最后一次操作变化 | 符合「手动偏好」语义；不额外合并 |
| 覆盖与 DSH 抽屉实际状态短暂不一致（转调失败） | 拉宽后按用户意图裁剪 | 意图优先，按钮/裁剪随后续上报自愈 |

## 10. 验证记录

| 日期 | 方式 | 结论 |
| --- | --- | --- |
| 2026-11-12 | 先红：新增抽屉态→拉宽 复现断言 | 失败于「AC-3 抽屉态点「显示」同时写覆盖」（旧实现不发 `dsh-sidebar-state`） |
| 2026-11-12 | 二次红：补 `sidebarOverride` 同步前 | 失败于「AC-1 拉宽到 900 → 仍按「显示」：不裁剪」（`crop=56`、按钮回落「显示」——页面覆盖态仍是 `null`，被去抖重算冲掉） |
| 2026-11-12 | 后绿：`TMPDIR=/tmp npm run test:one -- dsh-sidebar` | 通过：160 项断言 |
| 2026-11-12 | `TMPDIR=/tmp npm test` 全量 | 通过：1222 项断言 |
| 待补 | 实机：窄面板手动显示 → 拉宽到 900/1200 → 再拉回窄 | 需用户确认 |

> 排障指纹（诊断命令导出后可直接对照）：`hidden … ovr=0` 表示手动选择已写覆盖；
> `resize … skipped=1 ovr=0`（1s 最多一条）表示拖动已被覆盖接管、auto 未介入；
> 若出现 `recompute … hidden=1` 则说明 auto 又把侧栏藏回去了（本缺陷）。
