## 1. 背景与问题

**现象（真机，2026-11-02）**：在已有会话里继续提问、继续编辑文件时，点击**先前轮次**里出现过的
文件链接，打开的却是**最新一轮**的变更内容，并排 diff 的标题写着「文件 · 第 N 轮」，N 是最新一轮——
点的不是这一轮，看到的也不是这一轮。

**根因（代码链路已逐段确认）**：

1. 已有会话是从会话记录恢复的，早先消息常常没有 `data-chat-turn` 轮标记（011 第 1 节已记录的真机事实）；
   客户端 `turnOf()` 取不到轮次 → `coordsOf()` 按 011 AC-4 改发 `change = {sessionId, latest:true}`。
2. 宿主把它转成 `turn=latest` 问 `dsh-vscode-changes`，插件 `latestTurnOf()` **从大到小扫已记录的轮**，
   返回「这个文件最后一次被改动的那一轮」——续问里又改过同一文件时，那就是**最新一轮**。
3. 于是「点击所属轮」与「展示的轮」不一致：标题、内容都是别的轮（往往是最新的那轮）。
   工作区外文件另有同向问题：`openOutOfWorkspaceDiff` 在指定轮没有记录时也会自动换 `latest` 再查一次。

011 引入 `latest` 时的动机是「老会话链接不能只退 DSH 侧栏」，但它把**无法确定所属轮**的点击
升级成了「展示别的轮的变更」——这违反 005 的第一性原则（第 2 节：「若该文件在**点击所处的那个轮**
里被改动……标题写明轮次」「跨轮各自独立，不出现『累积到最新』的错觉」），也违反 005 AC-7
（无轮标记时**只发 `{path}`**，宿主直接走 P0）。用户判定：这种情况按 005 的降级链处理即可。

## 2. 目标

- 拿不到「点击所属轮」时**不再尝试展示任何轮级变更**：不发 `latest` 坐标、不接受 `latest` 坐标、
  路由不再提供 `turn=latest` 出口——任何路径都不可能展示别的轮的内容。
- 这类点击回到 005 的三级降级：P1（仅当点击所属轮已知）→ P0（HEAD ↔ 工作树）→ L0（普通打开）；
  工作区外文件回到 010/012 的既定行为（无坐标 → `no-coord` → 交回 DSH 侧栏，或 012 的显式兜底）。
- 点击所属轮**已知**且该轮确有该文件变更时，行为与 005 完全一致（并排 diff、标题写该轮轮次）。
- 011 中**不制造错觉**的部分不回退：相对路径按 DSH 会话 `cwd` 解析、客户端诊断日志。

## 3. 非目标

- 不做「从 DOM 反推历史消息所属轮」的新机制（风险大、需真机验证；011 的两条退路已到头）。
- 不动 005 的 P0（HEAD 对比）与 L0 降级、010 的工作区外轮级取数、012 的显式兜底开关。
- 不改 `cwd` 上报、握手协议、失败原因码与诊断日志（011 的其余部分）。
- 不改 `dsh-vscode-changes` 的取数口径（自捕获两侧全文 + `summary()` 权威清单、绝不按请求路径读盘）。

## 4. 用户故事

- 作为 **VS Code 用户**，我点先前轮次里的文件链接时，要么看到**那一轮**的变更，要么直接打开文件，
  绝不给我看另一轮（尤其最新一轮）的内容冒充。
- 作为 **DSH 二次开发者**，我希望「轮坐标」协议只有一个语义（具体轮次），不再有 second channel。
- 作为 **维护者**，我希望错觉类回归有一条明确的红/绿断言，下次改协议时先撞上它。

## 5. 验收标准（必须可执行）

- **AC-1**：Given `diffAndOpen`、会话已恢复（早先消息没有 `data-chat-turn`）、同一文件在更新的轮里
  也被改过，When 点击先前轮次里的该文件链接，Then 客户端**不带任何 `change` 坐标**（既不带 `turn`
  也不带 `latest`），宿主按 005 AC-7 走 P0/L0，**不出现**「第 N 轮」的轮级 diff。
  （断言：`file-link-client-sim` 无轮标记 → `reveal.change === undefined`；`file-link-diff`
  `sanitizeChangeCoord({latest:true}) === null` 且 `openDiffFor` 对 latest 坐标不查询轮级路由）
- **AC-2**：Given 点击所属轮已知且该轮记录里有该文件的两侧全文，When 点击，Then 照常打开该轮并排 diff、
  标题为「名称 · 第 N 轮」。（断言：`file-link-diff` P1 命中、`dsh-changes-plugin` 按具体轮次出数）
- **AC-3**：Given 点击所属轮已知但该轮没有记录 / 没有全文 / 没有该文件（`no-record`/`no-text`/`no-change`），
  When 点击，Then **不再**换 `latest` 重查：工作区内退 P0 → L0，工作区外按写法重试后仍失败则交回
  DSH 侧栏（012 开关除外），提示沿用 005 文案。（断言：`file-link-diff`
  `openOutOfWorkspaceDiff` 全程只查 `coord.turn`、不出现 `latest` 查询）
- **AC-4**：Given 旧版页面插件（0.2.7）仍发 `change = {sessionId, latest:true}`（扩展已升级、
  dsh web 未重启），When 中继收到，Then **不透传 `latest`**（只透传具体轮次），宿主按「无坐标」降级，
  不报错、不打开别的轮。（断言：`workspace-file-link` 中继脚本不含 `change.latest === true`
  且仍含具体轮次透传）
- **AC-5**：Given 路由收到 `turn=latest`（旧宿主或手工请求），When，Then 返回 400 `bad-request`；
  `turn` 非正整数、缺 `sessionId`/`path` 仍 400；按具体轮次查询仍只在已记录清单/自捕获记录里匹配，
  **绝不按请求路径读盘**。（断言：`dsh-changes-plugin` `turn=latest → 400`、既有 400/404 断言不减少）
- **AC-6**：Given 非 diff 模式 / 未握手 / 带修饰键的点击，When 点击，Then 行为与 001、005 AC-8 一致
  （不取 P1、不取 P0、回放原行为）。（断言：既有断言不减少）
- **AC-7**：Given 任意点击，Then 会话 `cwd` 上报、诊断环形日志、失败原因码与 011 一致（不回退）。
  （断言：`file-link-client-sim` cwd/日志断言保持通过）

## 6. 兼容矩阵

| 场景 | 新版 dsh（≥0.2.1） | 旧版 dsh | 说明 |
| --- | --- | --- | --- |
| Windows 本地 | 具体轮次 P1 → P0 → L0 | P0 → L0 | `latest` 出口全部移除 |
| macOS 本地 | 同上 | 同上 | 无平台分支 |
| Linux 本地 | 同上 | 同上 | 无平台分支 |
| WSL / SSH / 容器 | 同上（远端执行 git 与取数） | 同上 | 005 兼容矩阵不变 |
| 扩展已升级、dsh web 未重启（旧插件 0.2.7 发 latest） | 中继丢弃 latest → P0/L0 | — | AC-4 |
| 系统浏览器打开 DSH（非面板内） | 不接管 | 不接管 | 沿用 001 |

## 7. 约束（引用宪法）

- 第一条：不改 DSH 页面 DOM；本轮只删自己发的坐标与自己开的出口。
- 第三条：降级每一步仍可见（005 的状态栏文案原样保留）；本次删除的是「展示别的轮」这一出口，
  不新增静默路径——无坐标点击仍按 005 走 P0 并有提示。
- 第四条：协议字段可选不删形状——`change` 仍存在，只是只认具体轮次；旧插件发 `latest` 被丢弃而非报错。
- 第五条：路由仍只接受坐标、不接受任意路径读盘；净化函数仍只放行正整数轮次与合法 sessionId。
- 第六条：判定逻辑抽纯函数挂 `module.exports.__internals`（`sanitizeChangeCoord` 即是）。

## 8. 失败与提示

| 失败场景 | 用户可见提示（中文文案要点） | 出口动作 |
| --- | --- | --- |
| 无轮坐标（历史消息无标记） | 沿用 005：P0 命中开「与 HEAD 的差异」；P0 不可用则普通打开（无额外噪音） | 编辑器打开文件 |
| 该轮没改过这个文件 / 无记录 / 无全文 | 沿用 005 文案（「本轮没有该文件的变更」等） | P0 → L0 |
| 工作区外文件且无坐标（`no-coord`） | 沿用 010/012：「无法确定它属于哪一轮：已在 DSH 侧栏打开」+ 开关出路 | DSH 侧栏 / 012 显式兜底 |
| 旧插件发来的 `latest` | 无额外提示（按无坐标降级，行为可见） | 同第一行 |

## 9. 风险与开放问题

| 风险 / 未知 | 影响 | 应对 / 待验证 |
| --- | --- | --- |
| 历史消息仍无轮标记 → 这些链接永远看不到轮级 diff | 老会话链接多退到 P0/L0（005 的既定行为） | 这是本次的**预期**结果；若将来要「按链接所属历史轮出 diff」，需另立规格做「DOM 轮号 → 事件轮号」映射，不再用 `latest` |
| 旧宿主（1.0.7）+ 新插件（0.2.7） | 旧宿主请求 `turn=latest` 得 400 → 按 `error` 退 P0 | 插件随扩展同包分发、版本对齐安装，实际不会出现；出现也只是退 005 链，无错觉 |
| 用户仍看到「第 N 轮」diff 而点的是别的轮 | 说明还有未发现的坐标串轮路径 | 已断言 `latest` 三条出口全关；真机复验时用 `__dshVscodeFileLinks.log()` 核对 `change` 字段 |
